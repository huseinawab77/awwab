# AWWAB v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bikin ulang AWWAB sebagai web app (PWA) habit tracker dengan skor harian 0–100 dari rencana hari itu, 4 tab, tampilan Versi 3.

**Architecture:** Next.js App Router + Tailwind. Semua hitungan skor ada di modul murni `src/lib/score.ts` (dites dengan Vitest) yang menerima kebiasaan, catatan, dan jadwal manual, lalu mengembalikan rencana/skor/progres. Data di Supabase Postgres per baris dengan RLS; halaman membaca rentang tanggal sekali lalu menghitung di klien, dan menyimpan perubahan langsung (optimistic, dikembalikan kalau gagal).

**Tech Stack:** Next.js 15, React 19, TypeScript, Tailwind CSS 4, @supabase/ssr + @supabase/supabase-js, Vitest, Playwright (uji asap), Vercel.

**Spec:** `docs/superpowers/specs/2026-11-18-awwab-v2-design.md` + `DESIGN.md`

## Global Constraints
- Zona waktu **Asia/Jakarta** untuk "hari ini"; minggu mulai **Senin**; bulan = bulan kalender. Tanggal disimpan sebagai string `YYYY-MM-DD`.
- Skor D = `Math.round(100 * Σnilai / jumlahRencana)`; rencana kosong → `null` (hari santai, tidak ikut rata-rata).
- Semua kebiasaan nilainya sama; tanpa bobot.
- Semua teks UI bahasa Indonesia, sentence case, santai-netral ("Hari santai", "Semua beres hari ini. Mantap.").
- Token warna, huruf, radius, ukuran sentuh **≥ 44px** persis dari `DESIGN.md`; tidak ada warna di luar token.
- Format hitungan selalu `"2 dari 3"`.
- RLS aktif di setiap tabel: `user_id = auth.uid()`.
- Hari lalu bisa diedit maksimal **7 hari** ke belakang; hari depan tidak bisa diisi (hanya dijadwalkan di Minggu).
- Tanpa notifikasi, tanpa bahasa Inggris, tanpa goals/projects, tanpa bobot.

## Review Focus
1. Buka app jam 00:30 WIB (masih 17:30 UTC hari sebelumnya) → "hari ini" harus tanggal WIB baru. Test di Task 1.
2. Kebiasaan mingguan yang masuk lewat rutin **dan** jadwal manual **dan** dicatat → tetap dihitung sekali. Test di Task 2.
3. Kebiasaan dibuat Rabu atau diarsipkan Kamis → tidak muncul/terhitung di hari sebelum mulai atau sejak diarsipkan, tapi riwayatnya tetap. Test di Task 2.
4. Nilai angka 0, lewat target, desimal, atau diketik negatif/kosong → nilai per kebiasaan tidak lewat 1, input negatif/kosong ditolak. Test di Task 2 dan Task 6.
5. Simpan gagal (offline) atau ketuk dua kali cepat → nilai dikembalikan + pesan "Belum tersimpan, coba lagi"; satu baris per (kebiasaan, tanggal) lewat upsert. Test di Task 6.

### Task 2: Mesin skor

**Interfaces:**
- Consumes: `dates.ts`.
- Produces:
  ```ts
  type Period = "daily" | "weekly" | "monthly"; type Kind = "check" | "qty";
  interface Habit { id: string; name: string; kind: Kind; period: Period; unit: string | null;
    dayTarget: number | null; step: number | null; periodTarget: number | null;
    routineDays: number[]; sort: number; startOn: string; archivedOn: string | null }
  interface HabitLog { habitId: string; date: string; done: boolean; value: number | null }
  interface PlanEntry { habitId: string; date: string }
  type Source = "daily" | "routine" | "manual" | "logged";
  interface PlanItem { habit: Habit; source: Source; credit: number; done: boolean; value: number | null; over: boolean }
  isActive(h: Habit, d: string): boolean
  credit(h: Habit, log?: HabitLog): number                 // 0..1
  planFor(d: string, habits: Habit[], logs: HabitLog[], plans: PlanEntry[]): PlanItem[]
  dayScore(items: PlanItem[]): number | null
  averageScore(scores: (number | null)[]): number | null    // abaikan null, bulatkan
  periodRange(h: Habit, d: string): [string, string]         // minggu/bulan yang memuat d
  targetProgress(h: Habit, d: string, logs: HabitLog[]): { done: number; target: number; reached: boolean }
  habitConsistency(habits: Habit[], days: string[], logs: HabitLog[]):
    { best: { habit: Habit; done: number; of: number } | null; worst: { habit: Habit; done: number; of: number } | null }
  ```
  `planFor` mengembalikan non-harian dulu lalu harian, masing-masing urut `sort`. Prioritas source: `routine` > `manual` > `logged`. Log yang "ada" untuk source `logged` = `done === true` atau `value > 0`. `habitConsistency` hanya kebiasaan harian, hanya hari ≤ hari ini, butuh ≥ 3 hari aktif; best = rasio tertinggi, worst = terendah (seri → urutan `sort`), best ≠ worst.
